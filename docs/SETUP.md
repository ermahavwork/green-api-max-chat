# Локальный запуск и подключение MAX

## 1. Запуск

Установите Node.js 22.12+ или 24 LTS с npm. Затем:

```bash
git clone https://github.com/ermahavwork/green-api-max-chat.git
cd green-api-max-chat
npm ci
npm run dev
```

Откройте выведенный Vite адрес. Для проверки production-сборки:

```bash
npm run build
npm run preview
```

## 2. Подготовьте отдельный инстанс

1. Откройте [кабинет GREEN-API](https://console.green-api.com/), создайте инстанс именно **MAX** и подключите свой аккаунт мессенджера по инструкции кабинета. Статус должен быть `authorized`.
2. Скопируйте `idInstance`, `apiTokenInstance`, `apiUrl`. Пример API URL: `https://3100.api.green-api.com`. Используйте адрес своего инстанса: шард по номеру ID приложение не угадывает.
3. В настройках тестового инстанса включите `incomingWebhook: yes`. Для исходящих сообщений и статусов включите `outgoingAPIMessageWebhook`, `outgoingMessageWebhook`, `outgoingWebhook`.
4. Для HTTP-очереди `webhookUrl` должен быть пустым. Если существующий инстанс обслуживает другие приложения, создайте отдельный тестовый; не отключайте чужие webhooks. Приложение не изменяет настройки инстанса самостоятельно.
5. Откройте приложение, введите параметры и нажмите «Войти». Ключи не нужно помещать в `.env`, исходный код или GitHub.

## 3. Проверьте полный сценарий

1. Нажмите «Новый чат» и введите телефон согласованного тестового получателя в MAX: с кодом `+7` или `+375`.
2. После `checkAccount` приложение создаст чат по настоящему числовому `chatId`.
3. Напишите текст и отправьте его. «Принято API» ещё не означает доставку: статус обновляется при получении соответствующего события.
4. Ответьте с телефона получателя в MAX. Ответ должен появиться в этом же чате.
5. Попробуйте текст со ссылкой, несколько сообщений подряд и переключение диалогов.

**Без ключей:** кнопка «Открыть демо» показывает интерфейс и локальный автоматический ответ. Она не проверяет доставку в настоящий MAX.

## 4. Если не работает

| Симптом | Что проверить |
| --- | --- |
| Неверные данные / 401 | Токен, лишние пробелы, действующий инстанс |
| 403 / 404 | Адрес API из кабинета и idInstance; ограничения аккаунта |
| Инстанс не авторизован | Подключение MAX в кабинете, QR-код/подтверждение на телефоне |
| Отправка есть, ответов нет | `incomingWebhook: yes`, пустой webhookUrl, другой потребитель очереди |
| «Подключение…» во второй вкладке | Закройте первую вкладку с этим инстансом или выйдите из неё |
| Проверка номера недоступна / 469 | Лимит `checkAccount`, тариф, состояние инстанса |
| Связь прервана | Интернет, доступность API, расширения браузера/CORS; получатель автоматически переподключится |
| Результат отправки неизвестен | Проверьте сообщение в MAX перед повтором; автоматической повторной отправки нет |

Подробности: [официальная документация HTTP-очереди](https://green-api.com/v3/docs/api/receiving/technology-http-api/).

## 5. Публикация

GitHub Actions собирает приложение и публикует `dist` в GitHub Pages при push в `main`. В Settings → Pages источником должен быть GitHub Actions. Рабочие ключи для сборки не требуются. При публикации на другом статическом HTTPS-хостинге загрузите содержимое `dist`; Vite использует относительные пути.
